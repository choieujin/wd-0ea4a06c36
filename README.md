# 모바일 청첩장

순수 HTML/CSS/JS로 만든 정적 사이트이며 GitHub Pages로 배포됩니다.

---

## 변경사항 반영 방법

### 1. 코드·내용 수정 → 푸시만 하면 됩니다 ✅

`main` 브랜치에 푸시하면 GitHub Pages가 **자동으로 다시 빌드·배포**합니다. (약 1분)

```bash
git add .
git commit -m "수정 내용"
git push
```

표지 교체, 글자/색 수정, 계좌번호 변경, 안내문 수정 등은 전부 **푸시만** 하면 반영됩니다.

### 2. 갤러리 사진 추가/삭제/교체 → 빌드 한 번 필요 ⚠️

갤러리는 `assets/js/gallery-list.js`(사진 파일명 목록)를 보고 그립니다. 이 목록은 자동으로 갱신되지 않으므로, **사진을 바꿀 때만** 빌드 스크립트를 한 번 돌려야 합니다.

```bash
# 1) assets/gallery/ 에 사진을 넣거나 빼고
bash scripts/build-gallery.sh    # gallery-list.js 자동 갱신 (+ cwebp 있으면 WebP 변환)

# 2) 평소처럼 배포
git add .
git commit -m "사진 업데이트"
git push
```

### 정리

| 작업 | 빌드 필요? | 명령 |
|---|---|---|
| 글자·색·계좌·안내 등 수정 | ❌ | `add → commit → push` |
| 표지(main.jpg) 교체 | ❌ | 같은 파일명으로 덮어쓰고 push |
| **갤러리 사진 추가/삭제/교체** | ✅ | `build-gallery.sh` → `add → commit → push` |

## 축하 메시지 (방명록)

갤러리 아래에 하객이 축하 메시지를 남기는 섹션이 있습니다. **DB는 쓰지 않습니다.**

```
하객이 작성  →  구글 폼으로 전송  →  구글 시트에 한 줄씩 쌓임
                                        ↓
                       청첩장 화면이 그 시트를 읽어서 표시
```

GitHub Pages 는 정적 호스팅이라 글을 받아줄 서버가 없는데, 구글 폼이 그 역할을 대신합니다.
서버를 띄울 필요도, Apps Script 를 배포할 필요도 없습니다.

### 설정 — 두 방법 중 하나 (시트에서 다 됩니다)

`assets/js/guestbook-config.js` 한 파일만 채우면 됩니다.

#### ⓐ 시트 스크립트 방식 (권장)

폼을 따로 만들지 않고 시트 안에서 끝냅니다. 글이 **즉시** 반영됩니다.

하객에게는 **메시지 한 칸만** 보여줍니다 — 이름도 비밀번호도 받지 않습니다.
그래서 하객이 자기 글을 지울 수는 없고, 지울 일이 있으면 시트에서 그 행을 삭제하면 됩니다.

1. 시트 상단 **[확장 프로그램] → [Apps Script]** 를 열고, 기본 코드를 지운 뒤
   `apps-script/Code.gs` 내용을 통째로 붙여넣고 저장
2. 함수 목록에서 **`setup`** 을 골라 한 번 실행 (권한 승인 창 → 허용)
   → 시트에 `guestbook` 탭이 생깁니다
3. **[배포] → [새 배포] → 웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**  ← 하객이 로그인 없이 쓰려면 필수
4. 나온 `https://script.google.com/macros/s/.../exec` 주소를
   `guestbook-config.js` 의 **`webAppUrl`** 에 붙여넣기

> 스크립트를 고친 뒤에는 **[배포] → [배포 관리] → ✏ → 버전 "새 버전" → [배포]** 를 해야 반영됩니다.
> 저장만으로는 웹 앱 동작이 바뀌지 않습니다. 주소는 그대로 유지되므로 설정은 안 건드려도 됩니다.

`apps-script/Code.gs` 를 고쳤다면 **시트에 붙여넣은 코드도 같이 갱신하고 재배포**해야 합니다.
안 하면 청첩장과 스크립트의 규칙이 어긋나 메시지 등록이 실패합니다.

#### ⓑ 구글 폼 방식

폼을 만들어 [응답] 탭에서 이 시트에 연결한 뒤, `formAction`(폼 주소의 `/viewform` → `/formResponse`)과
`fields`(폼 ⋮ → "미리 채워진 링크 가져오기" 로 얻은 `entry.숫자` 2개), `sheetId` 를 채웁니다.
시트는 **[공유] → 링크가 있는 모든 사용자 · 뷰어** 로 둡니다.

이 방식은 하객이 자기 글을 지울 수 없고(시트에서 행 삭제), 다른 사람 화면에 뜨기까지
몇 분 걸릴 수 있습니다.

둘 다 비워두면 방명록은 **읽기 전용**으로 표시됩니다. 사이트는 정상 동작합니다.

### 알아둘 점

- **ⓑ 폼 방식**은 다른 사람 화면에 뜨기까지 최대 1~5분 걸릴 수 있습니다(구글 시트 읽기 캐시).
  글을 쓴 본인 화면에는 곧바로 "방금 전 · 곧 반영됩니다" 로 표시되고, 시트에 올라오면 자동 교체됩니다.
  **ⓐ 스크립트 방식**은 즉시 반영됩니다.
- **이름을 받지 않으므로 누가 썼는지는 남지 않습니다.** 메시지 본문에 이름을 적어 주시는 분도 있을 겁니다.
- 어느 방식이든 **시트에서 행을 지우면** 그 메시지는 사라집니다. 하객이 직접 지울 수는 없습니다.
- 접수 주소는 공개돼 있어 이론상 장난 글이 올 수 있습니다. 식 전후로 시트를 한 번씩 봐주세요.
- 시트 공유 권한은 **뷰어**로 두세요. 편집자로 열어두면 링크를 아는 사람이 메시지를 지울 수 있습니다.

### 로컬에서 서버로 받고 싶다면 (선택)

구글을 쓰지 않고 파일에 직접 저장하는 방식도 그대로 남아 있습니다.
`guestbook-config.js` 를 비워둔 채 아래처럼 띄우면 `assets/data/guestbook.json` 에 저장되고,
이 경로에서도 이름·비밀번호는 선택 사항입니다. 비밀번호를 함께 보내면 그 글은 본인이 삭제할 수 있습니다.

```bash
node server.mjs            # http://localhost:8765
PORT=3000 node server.mjs  # 포트 변경
GUESTBOOK_ADMIN_KEY=원하는키 node server.mjs   # 관리자 삭제용 키
```

### 한글·이모지가 깨지지 않게 하는 규칙

수정할 일이 있다면 아래를 유지해 주세요.

- 폼 전송은 `URLSearchParams`(UTF-8 폼 인코딩)로 보냅니다.
- 글자 수 제한은 `String.length` 가 아니라 **코드포인트**(`Array.from`) 기준 — 이모지가 반쪽으로 잘리지 않습니다.
- 서버(`server.mjs`)를 고칠 때는 파일 상단 주석의 5가지 규칙을 지켜 주세요.
  (본문 한 번에 UTF-8 디코딩 · 파일 IO `utf8` 명시 · 응답 `charset=utf-8` · 저장 전 NFC 정규화 · 코드포인트 기준 길이)

## 참고

- **이미지 최적화:** `brew install webp` 후 `build-gallery.sh`를 실행하면 사진을 WebP로 변환해 용량을 크게 줄여줍니다(모바일 로딩 속도 개선).
- **주소 변경:** 레포 이름을 바꾸면 공개 주소도 바뀝니다 (`gh repo rename <새이름>`).
- **공개 범위:** 무료 GitHub Pages는 public 레포에서만 동작합니다. 사이트 접속자는 누구나 사진·계좌를 볼 수 있으니 주소 공유에 유의하세요.
